Aldwin · conversation
Say what happened. Show the work only when asked.
No setup: every launch opens straight to the field, under a short card of what Aldwin is working with. Aldwin reads and runs without asking and says what it is doing, but it never edits directly: every edit opens as a review, and nothing is saved until you approve. The footer always opens with a state glyph in the mark column: amber ● blinking while Aldwin works, grey ○ when it is idle or waiting. While working it says what Aldwin is doing and how long it has been at it; esc always stops, so no key is named. Three text tones, one accent, and colour only where it carries meaning. Every screen leads with a sentence a first-time user can read, and the technical detail sits one disclosure below it, exact and unabridged.

Aldwin · working
Something is always moving while Aldwin works.
The status line says what Aldwin is doing right now in a few plain words: reading a file, finding something, writing something. Each new phrase types in, then a highlight runs along it while it holds, so the line is never still and is always readable. In the mark column, the running ● blinks to ○ and back every half second, in amber, the same glyphs the plan uses. The timer counts in minutes and seconds, dimmed, right after the phrase. There is no key hint: esc always stops, and the launch card says so once. The context bar drops its label and, with the row to itself, its ten segments grow from the thin ━ to the full █ block, whose top sits level with the digits beside it; the percent sits after it and the filled end ramps toward full accent as before. If nothing new happens for 30 seconds, the ● stops blinking and sits as a grey ○ and the phrase starts with "Still", so a stall looks different from progress. All of it is per-cell glyphs and foreground colour at 10 frames a second, so it runs in any truecolor terminal.

Aldwin · review
The code is the content.
Aldwin never edits directly: every edit opens as a review, and nothing is saved until you approve. Blue means you: your selection, your comments, your next action, and nothing else. Select lines and the field says which lines you are commenting on; ↩ adds the comment, which sits at the end of its line so the code is never broken up. Unchanged code folds away, and the keys live behind ?. ⌃↩ stays grey until every file is read, then turns blue. When you approve, the review folds back into the conversation as one line you can open again.
